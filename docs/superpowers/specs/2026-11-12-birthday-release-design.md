# Открытие подарка в день рождения

Владелец выбрал проверку времени в браузере, московский часовой пояс и обращение
«Карамельная попка». Ссылка QR остаётся `https://vadikzyryanov.github.io/gift/`.

- Production: до `2026-11-18T00:00:00+03:00` показываем личное обращение,
  короткий текст ожидания и отсчёт дней, часов, минут, секунд.
- После наступления даты появляется кнопка «Открыть подарок». Уже открытая
  страница обновляет состояние сама, в том числе после возвращения из фона.
- Время сравниваем с абсолютной датой с явным смещением `+03:00`, поэтому
  часовой пояс устройства не меняет момент открытия. Часы устройства должны
  быть выставлены правильно; защиту от сознательного обхода не добавляем.
- `npm run dev` сразу открывает существующую игру. Production preview
  использует тот же экран ожидания, что и GitHub Pages.
- Игра подключается через lazy import после открытия подарка. При ошибке
  загрузки, включая устаревший chunk после очередной публикации, предлагаем
  обновить страницу. Сохранения и игровую логику не меняем.
- Оформление использует текущую палитру и локальные шрифты, адаптируется
  к телефону. Отсчёт не озвучивается screen reader каждую секунду;
  появление доступного подарка объявляется один раз.

## Подходы

Выбрана клиентская проверка: подходит существующему статическому сайту без
дополнительных сервисов. Серверная проверка и удержание контента лучше
защищают от обхода, но требуют backend. Публикация по расписанию не подходит
для точного открытия: очередь GitHub Actions может задержать выполнение.

## Границы и проверка

Нет новых зависимостей, изменения workflow или новых веток. После просмотра
временного 30-секундного preview владелец поручил удалить этот режим и выполнить
commit и push экрана ожидания. Текущий workflow публикует каждый push в master.
Отсчёт сам по себе не обновляет уже загруженную страницу до последней
опубликованной версии.

По пользовательским инструкциям тесты не создавать и не запускать.
Проверить production build (включает typecheck), lazy chunk и итоговый diff.
